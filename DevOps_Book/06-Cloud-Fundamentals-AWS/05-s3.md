# Chapter 5 — S3 — Simple Storage Service

## Learning Objectives

By the end of this chapter, you will be able to:

- Explain S3's object storage model and when to use it
- Create buckets, upload objects, and manage them with the AWS CLI
- Choose the right storage class to minimize cost
- Configure lifecycle policies for automated storage tier transitions
- Secure buckets with policies, block public access, and encryption
- Use versioning, static website hosting, pre-signed URLs, and event notifications

---

## 5.1 What Is S3?

**S3 (Simple Storage Service)** is AWS's object storage service — you store any file as a discrete object identified by a key. It is not a filesystem; there is no hierarchy (the "/" characters in key names simulate folders but they are just part of the key string).

Key characteristics:

- **Global service**, but buckets are created in a specific region
- **Unlimited storage** — store as many objects as you want
- **Objects up to 5TB** each (use multipart upload for files over 100MB)
- **11 nines of durability** (99.999999999%) — AWS stores objects across 3+ Availability Zones
- **99.99% availability** for the Standard storage class
- Accessed via HTTPS — no VPC required, though VPC Endpoints are recommended

Common use cases: static website hosting, media storage, backups, data lakes, log archives, application assets, software distribution.

---

## 5.2 Core Concepts

| Concept | Description |
|---|---|
| **Bucket** | Container for objects. Name is globally unique across all AWS accounts. |
| **Object** | A file plus its metadata. Immutable — to update, you upload a new version. |
| **Key** | The full path/name of an object: `logs/2024/01/app.log` |
| **Prefix** | The key path up to (not including) the filename: `logs/2024/01/` |
| **Versioning** | Keep multiple versions of the same object key |
| **Region** | Bucket data stays in the region you choose unless you replicate it |

```bash
# Create bucket
aws s3 mb s3://my-unique-bucket-name-2024 --region us-east-1

# Upload files
aws s3 cp file.txt s3://my-bucket/file.txt
aws s3 sync ./local-dir s3://my-bucket/prefix/      # sync entire directory

# Download
aws s3 cp s3://my-bucket/file.txt ./file.txt
aws s3 sync s3://my-bucket/prefix/ ./local-dir

# List
aws s3 ls s3://my-bucket/
aws s3 ls s3://my-bucket/prefix/ --recursive

# Delete
aws s3 rm s3://my-bucket/file.txt
aws s3 rm s3://my-bucket/prefix/ --recursive
```

> **Bucket naming rules**: 3–63 characters, lowercase letters/numbers/hyphens only, must start with a letter or number, cannot look like an IP address. The name must be globally unique — `my-bucket` is almost certainly taken.

## 5.3 S3 Storage Classes

S3 offers multiple storage classes with different cost/access tradeoffs. Choose based on how often you access the data.

| Class | Availability | Retrieval | Cost | Use Case |
|---|---|---|---|---|
| **Standard** | 99.99% | Immediate | Highest | Frequently accessed data |
| **Standard-IA** | 99.9% | Immediate | Lower | Infrequent access, but fast when needed |
| **One Zone-IA** | 99.5% | Immediate | Lower | Infrequent, can recreate if lost |
| **Intelligent-Tiering** | 99.9% | Immediate | Auto | Unknown or changing access patterns |
| **Glacier Instant** | 99.9% | Immediate | Very low | Archives accessed ~1/quarter |
| **Glacier Flexible** | 99.99% | 1 min – 12h | Very low | Long-term backups |
| **Glacier Deep Archive** | 99.99% | Up to 48h | Lowest | 7+ year retention, rarely accessed |

> **Cost structure**: Standard-IA and One Zone-IA have a minimum storage duration of 30 days and a per-GB retrieval fee. Glacier classes have 90-day minimums. Factor in retrieval costs when choosing — a class with lower storage costs may be more expensive overall if you retrieve data frequently.

## 5.4 Lifecycle Policies

Lifecycle policies automate moving objects between storage classes and deleting old objects — saving money without manual work.

```json
{
  "Rules": [{
    "ID": "auto-archive",
    "Status": "Enabled",
    "Transitions": [
      {
        "Days": 30,
        "StorageClass": "STANDARD_IA"
      },
      {
        "Days": 90,
        "StorageClass": "GLACIER"
      }
    ],
    "Expiration": {
      "Days": 365
    }
  }]
}
```

```bash
aws s3api put-bucket-lifecycle-configuration \
  --bucket my-bucket \
  --lifecycle-configuration file://lifecycle.json
```

This policy:

1. Moves objects to Standard-IA after 30 days (lower storage cost)
2. Moves objects to Glacier after 90 days (much lower storage cost)
3. Permanently deletes objects after 365 days

You can also scope rules to a prefix (`logs/`) or objects with specific tags, so different data types follow different rules within the same bucket.

## 5.5 S3 Security

S3 is **private by default** — no public access unless you explicitly allow it. Three layers of access control:

1. **Block Public Access** — account-level or bucket-level setting that overrides all other policies
2. **Bucket Policy** — JSON resource policy attached to the bucket
3. **IAM Policy** — attached to users/roles, controls what they can do

```bash
# Block all public access (recommended default)
aws s3api put-public-access-block \
  --bucket my-bucket \
  --public-access-block-configuration \
    "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"

# Bucket policy example: allow only specific IAM role
aws s3api put-bucket-policy --bucket my-bucket --policy '{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {
      "AWS": "arn:aws:iam::123456789:role/app-role"
    },
    "Action": ["s3:GetObject", "s3:PutObject"],
    "Resource": "arn:aws:s3:::my-bucket/*"
  }]
}'

# Enable encryption at rest (AES-256 managed by AWS)
aws s3api put-bucket-encryption \
  --bucket my-bucket \
  --server-side-encryption-configuration '{
    "Rules": [{"ApplyServerSideEncryptionByDefault": {"SSEAlgorithm": "AES256"}}]
  }'
```

> **Security best practice**: Enable Block Public Access at the account level. Then selectively relax it only for buckets that genuinely need public access (like a static website bucket). Encryption at rest is free with SSE-S3 (AES-256) — always enable it.

## 5.6 S3 Versioning

Versioning keeps every version of every object. Protects against accidental deletes and overwrites.

- Once enabled, versioning cannot be disabled — only suspended
- Deleting an object with versioning creates a **delete marker** (the object is hidden, not gone)
- Storage costs increase because old versions are retained

```bash
# Enable versioning
aws s3api put-bucket-versioning \
  --bucket my-bucket \
  --versioning-configuration Status=Enabled

# List versions
aws s3api list-object-versions --bucket my-bucket --prefix myfile.txt

# Restore old version (download it, then re-upload as the current version)
aws s3api get-object \
  --bucket my-bucket \
  --key myfile.txt \
  --version-id xxxxxxxxxxxxxxxx \
  restored-file.txt

# Delete a specific version (permanent — no delete marker created)
aws s3api delete-object \
  --bucket my-bucket \
  --key myfile.txt \
  --version-id xxxxxxxxxxxxxxxx
```

> **Tip**: Combine versioning with lifecycle policies to expire non-current versions after N days. Without this, old versions accumulate and your storage bill grows unbounded.

## 5.7 Static Website Hosting

S3 can serve static files (HTML, CSS, JS, images) as a website — no server required.

```bash
# Enable static website hosting
aws s3api put-bucket-website \
  --bucket my-website-bucket \
  --website-configuration '{
    "IndexDocument": {"Suffix": "index.html"},
    "ErrorDocument": {"Key": "404.html"}
  }'

# Bucket policy for public read (must also disable Block Public Access first)
aws s3api put-bucket-policy --bucket my-website-bucket --policy '{
  "Statement": [{
    "Effect": "Allow",
    "Principal": "*",
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::my-website-bucket/*"
  }]
}'

# Upload site
aws s3 sync ./dist s3://my-website-bucket/ --delete

# Website URL: http://my-website-bucket.s3-website-us-east-1.amazonaws.com
# For HTTPS: put CloudFront in front (Chapter 8)
```

> **Limitations of S3 website hosting**: HTTP only (not HTTPS), no custom domain without Route 53, no server-side logic. For production, always put CloudFront in front — it adds HTTPS, a CDN, custom domains, and caching.

## 5.8 Pre-signed URLs

Pre-signed URLs grant temporary access to private objects without changing bucket permissions. Useful for letting users download or upload files directly.

```bash
# Generate a temporary URL for private object (expires in 1 hour)
aws s3 presign s3://my-bucket/private-file.pdf --expires-in 3600

# Returns:
# https://my-bucket.s3.amazonaws.com/private-file.pdf?X-Amz-Algorithm=...&X-Amz-Expires=3600&...
# Anyone with this URL can access the file until it expires
```

Use cases:

- Let users download their own files from a private bucket
- Let users upload files directly to S3 (bypass your server — saves bandwidth)
- Share a private asset temporarily with an external party

> **Security note**: The URL is generated using the credentials of whoever creates it. If using an IAM role, the URL expires when the role's credentials expire — which may be sooner than the `expires-in` you specified.

## 5.9 S3 Event Notifications

S3 can trigger actions when objects are created, deleted, or restored. Events can be sent to Lambda, SQS, or SNS.

```bash
# Trigger Lambda when a .jpg object is uploaded
aws s3api put-bucket-notification-configuration \
  --bucket my-bucket \
  --notification-configuration '{
    "LambdaFunctionConfigurations": [{
      "LambdaFunctionArn": "arn:aws:lambda:us-east-1:123:function:process-upload",
      "Events": ["s3:ObjectCreated:*"],
      "Filter": {
        "Key": {"FilterRules": [{"Name": "suffix", "Value": ".jpg"}]}
      }
    }]
  }'
```

Common event-driven patterns:

- **Image processing**: resize/compress images on upload
- **ETL pipelines**: trigger Glue or Lambda when a new data file lands
- **Notifications**: send SNS alert when a critical file arrives
- **Cross-region sync**: replicate objects to another bucket/region

---

## Summary

- S3 is object storage — not a filesystem. Objects are stored by key (a string), not in a true directory hierarchy.
- Buckets are globally unique; objects have 11 nines of durability across 3+ AZs.
- Choose the right storage class based on access frequency — lifecycle policies automate transitions to save money.
- S3 is private by default. Use Block Public Access, bucket policies, and IAM policies to control access.
- Versioning protects against accidental overwrites and deletes — combine with lifecycle rules to manage old versions.
- Static website hosting is simple and cheap; add CloudFront for HTTPS and CDN performance.
- Pre-signed URLs grant temporary, expiring access to private objects without changing bucket permissions.
- Event notifications let S3 trigger serverless workflows when objects are uploaded or modified.
