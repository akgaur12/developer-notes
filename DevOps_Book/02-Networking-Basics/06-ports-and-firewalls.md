## 6.1 What Is a Firewall?

A **firewall** filters network traffic based on rules — allowing or blocking packets based on source IP, destination IP, port, and protocol.

```
Internet → [Firewall] → Your Server

Firewall rules (evaluated top to bottom):
  ALLOW  TCP  from ANY      to port 22    (SSH)
  ALLOW  TCP  from ANY      to port 80    (HTTP)
  ALLOW  TCP  from ANY      to port 443   (HTTPS)
  ALLOW  TCP  from 10.0.0.0/8 to port 5432  (DB from internal only)
  DENY   ALL  from ANY      to ANY        (default deny everything else)
```

### Types of Firewalls

| Type | Where | Examples |
|------|-------|---------|
| **Host-based** | On the server itself | UFW, iptables, Windows Firewall |
| **Network-based** | At network edge | Cisco ASA, Palo Alto |
| **Cloud security groups** | Cloud provider level | AWS SGs, GCP Firewall Rules |
| **WAF (Web Application Firewall)** | Application layer | Cloudflare, AWS WAF |

## 6.2 UFW — Uncomplicated Firewall

UFW is the user-friendly frontend for iptables on Ubuntu/Debian:

```bash
# Status
sudo ufw status
sudo ufw status verbose    # more detail
sudo ufw status numbered   # with rule numbers

# Enable / Disable
sudo ufw enable
sudo ufw disable

# Default policies (set before adding rules)
sudo ufw default deny incoming     # block all inbound by default
sudo ufw default allow outgoing    # allow all outbound by default
```

### Adding Rules

```bash
# Allow by service name (uses /etc/services)
sudo ufw allow ssh
sudo ufw allow http
sudo ufw allow https

# Allow by port number
sudo ufw allow 22
sudo ufw allow 80
sudo ufw allow 443
sudo ufw allow 8080

# Allow specific protocol
sudo ufw allow 53/tcp
sudo ufw allow 53/udp

# Allow port range
sudo ufw allow 9000:9100/tcp

# Allow from specific IP
sudo ufw allow from 203.0.113.5

# Allow from specific IP to specific port
sudo ufw allow from 10.0.0.0/8 to any port 5432    # PostgreSQL from internal
sudo ufw allow from 192.168.1.0/24 to any port 22  # SSH from home network only

# Allow on specific interface
sudo ufw allow in on eth0 to any port 80
```

### Blocking Rules

```bash
# Block port
sudo ufw deny 3306      # block MySQL from external

# Block IP (e.g., brute force attacker)
sudo ufw deny from 203.0.113.100

# Block IP range
sudo ufw deny from 198.51.100.0/24
```

### Deleting Rules

```bash
# Delete by rule number
sudo ufw status numbered
sudo ufw delete 3        # delete rule number 3

# Delete by matching rule
sudo ufw delete allow 8080
sudo ufw delete allow from 10.0.0.0/8 to any port 5432
```

### UFW for Common DevOps Setups

```bash
# Web server (nginx/Apache)
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable

# Application server (behind load balancer, no direct public access)
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow from 10.0.0.0/8 to any port 22    # SSH from internal only
sudo ufw allow from 10.0.1.0/24 to any port 8080  # App port from LB subnet
sudo ufw enable

# Database server (only accessible from app subnet)
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow from 10.0.10.0/24 to any port 5432  # PostgreSQL from app servers
sudo ufw allow from 10.0.0.5 to any port 22         # SSH from bastion only
sudo ufw enable
```

## 6.3 iptables — The Linux Firewall Engine

UFW is a frontend for **iptables** — the actual Linux firewall. Understanding iptables lets you handle complex scenarios UFW can't express.

### iptables Architecture

```
Incoming packet
      ↓
  PREROUTING (NAT chain)
      ↓
  INPUT chain → If destined for local process
      ↓
  Local process
      ↓
  OUTPUT chain → If generated by local process
      ↓
  POSTROUTING (NAT chain)
      ↓
  FORWARD chain → If forwarding to another host
```

### Tables

| Table | Purpose |
|-------|---------|
| `filter` | Default — allow/deny packets |
| `nat` | Network address translation |
| `mangle` | Modify packet headers |
| `raw` | Connection tracking bypass |

### Basic iptables Commands

```bash
# View rules
sudo iptables -L                    # filter table
sudo iptables -L -n -v              # verbose, numeric (no DNS lookups)
sudo iptables -L -n -v --line-numbers  # with rule numbers
sudo iptables -t nat -L             # NAT table

# Add rules (append to chain)
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT    # allow HTTP
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT   # allow HTTPS
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT    # allow SSH
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT  # allow established
sudo iptables -A INPUT -j DROP                         # default deny

# Insert at specific position
sudo iptables -I INPUT 1 -p tcp --dport 8080 -j ACCEPT  # insert at position 1

# Delete rule by number
sudo iptables -D INPUT 3

# Delete rule by specification
sudo iptables -D INPUT -p tcp --dport 8080 -j ACCEPT

# Set default policy
sudo iptables -P INPUT DROP         # default deny all input
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

# Flush (delete all rules)
sudo iptables -F          # flush all
sudo iptables -F INPUT    # flush INPUT chain only
```

### Saving iptables Rules (Persist Across Reboots)

```bash
# Ubuntu/Debian
sudo apt install iptables-persistent
sudo netfilter-persistent save
sudo netfilter-persistent reload

# Or manually
sudo iptables-save > /etc/iptables/rules.v4
sudo iptables-restore < /etc/iptables/rules.v4
```

### Common iptables Patterns

```bash
# Allow established connections (before DROP rule)
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Allow loopback
sudo iptables -A INPUT -i lo -j ACCEPT

# Rate limit SSH (brute force protection)
sudo iptables -A INPUT -p tcp --dport 22 -m state --state NEW \
  -m recent --set --name SSH
sudo iptables -A INPUT -p tcp --dport 22 -m state --state NEW \
  -m recent --update --seconds 60 --hitcount 4 --name SSH -j DROP

# Log dropped packets
sudo iptables -A INPUT -j LOG --log-prefix "IPTables-Dropped: "
sudo iptables -A INPUT -j DROP
```

## 6.4 Cloud Security Groups

Cloud providers implement firewalls at the infrastructure level — traffic is filtered before it even reaches your VM.

### AWS Security Groups

```bash
# AWS SG rules (via AWS CLI)
aws ec2 authorize-security-group-ingress \
  --group-id sg-12345678 \
  --protocol tcp \
  --port 80 \
  --cidr 0.0.0.0/0    # allow HTTP from anywhere

aws ec2 authorize-security-group-ingress \
  --group-id sg-12345678 \
  --protocol tcp \
  --port 5432 \
  --source-group sg-87654321   # allow PostgreSQL from app security group only
```

### Cloud Firewall Concepts

```
AWS Security Group: stateful — if you allow inbound, response traffic auto-allowed
AWS NACL:          stateless — need rules for both inbound and outbound
GCP Firewall:      stateful by default
Azure NSG:         stateful
```

**Stateful vs Stateless:**
- **Stateful**: tracks connections; if inbound is allowed, outbound response is automatically allowed
- **Stateless**: every packet evaluated independently; must explicitly allow return traffic

## 6.5 Port Knocking (Security Through Obscurity)

**Port knocking** hides SSH behind a sequence of "knocks":

```bash
# Install knockd
sudo apt install knockd

# /etc/knockd.conf:
[openSSH]
    sequence    = 7000,8000,9000
    seq_timeout = 5
    command     = /sbin/iptables -A INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
    tcpflags    = syn

# To connect: knock on 7000, 8000, 9000 then SSH
knock serverip 7000 8000 9000
ssh user@serverip
```

## 6.6 Firewall Debugging

```bash
# Test if port is accessible
nc -zv hostname port
curl -m 3 http://hostname:port

# Check if UFW is blocking something
sudo ufw status verbose

# Watch iptables drop in real time
sudo iptables -A INPUT -j LOG --log-prefix "FW-DROP: "
sudo tail -f /var/log/kern.log | grep "FW-DROP"
# Clean up after debugging:
sudo iptables -D INPUT -j LOG --log-prefix "FW-DROP: "

# See which rule matches a packet
sudo iptables -L INPUT -n -v     # packet counts show which rules are hit
```

## Summary

```
UFW (simple):
  sudo ufw default deny incoming
  sudo ufw allow 22
  sudo ufw allow 80
  sudo ufw allow 443
  sudo ufw enable

iptables (advanced):
  iptables -A INPUT -p tcp --dport 80 -j ACCEPT
  iptables -A INPUT -j DROP

Best practice:
  Default DENY everything incoming
  Explicitly ALLOW only what's needed
  Restrict database ports to internal network only
  Rate-limit SSH to prevent brute force
```

## Hands-On Exercise

```bash
# 1. Check current UFW status
sudo ufw status verbose

# 2. Set up a proper firewall for a web server
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status

# 3. Allow only localhost to access port 3000
sudo ufw allow from 127.0.0.1 to any port 3000
sudo ufw deny 3000    # deny from everywhere else
sudo ufw status numbered

# 4. Test with nc
nc -zv localhost 80 2>&1   # should succeed
nc -zv localhost 5432 2>&1 # should fail (not opened)

# 5. View iptables rules (UFW manages these)
sudo iptables -L INPUT -n -v --line-numbers | head -20

# 6. Clean up test rule
sudo ufw delete allow from 127.0.0.1 to any port 3000
sudo ufw delete deny 3000
```
